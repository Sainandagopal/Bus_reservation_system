# Mango — Spring Boot + React Bus Reservation System

Mango is a payment-free bus reservation application built with a **Java Spring Boot backend** and a **React + TypeScript frontend**. The recommended local run mode builds React into Spring Boot's static resources so the full website and REST API share one HTTPS origin:

**https://localhost:8080**

There is no Razorpay, UPI, checkout, or payment integration in this project.

## Why the URL was previously `http://localhost:5173`

The earlier setup ran Vite's React development server separately from Spring Boot. Vite served the UI on `http://localhost:5173`, while Spring Boot served APIs on `http://localhost:8080`. Neither process automatically enables HTTPS. This version changes the launch flow:

1. Build React with Vite.
2. Copy the generated React files into `backend/src/main/resources/static/`.
3. Generate a local self-signed HTTPS certificate using the JDK's `keytool`.
4. Package the Java backend and React files together into one Spring Boot executable JAR.
5. Run that JAR with HTTPS on port `8080`.

The single main address is **https://localhost:8080**. The URL is HTTPS, not HTTP. The self-signed certificate is only for local development; your browser may initially display a certificate warning. See **Local HTTPS certificate** below.

## Features

### Traveller
- Register and sign in.
- Search buses by source, destination, date, and category.
- View bus names, journey times, category, fare, and availability.
- Select a seat on the 37-seat map.
- Confirm a booking with **Book the Seat** — no payment step.
- View the signed-in user's reservations and cancel eligible bookings.

### Admin
- Admin-only dashboard and protected API operations.
- Create, edit, and deactivate bus routes.
- Manage bus names/codes, route, departure/arrival times, category, and fare.
- View and cancel eligible reservations.

### Categories and seat rules
- AC Sleeper
- AC Seater (Semi-Sleeper)
- Non-AC Sleeper
- Non-AC Seater

The Java backend enforces exactly **37 seats** numbered `1` through `37`; capacity is not a user-editable field. The backend validates bookings and uses a bus database lock to help prevent concurrent seat conflicts. Green seats are available, blue is selected, and red is booked. Route availability changes to red at five or fewer seats remaining and shows fully booked at zero availability.

## Stack

- **Java 21**
- **Spring Boot 3.5.16** — REST API and serves the built React UI
- Spring Security, Spring Data JPA, Bean Validation
- **React 19 + TypeScript + Vite**
- CSS and Lucide icons
- H2 file-backed database stored under `backend/data/`
- HTTPS with a locally generated PKCS12 certificate
- No payments and no external payment-provider keys

## Requirements

- Windows 10/11 and PowerShell
- JDK 21
- Internet access during first startup to retrieve Maven/Node if they are missing and install React packages

The scripts can download Maven and a portable Node.js distribution into your user/project folders if compatible installations are not found. They do not require a global Node.js MSI installation. The React build requires the npm registry to be reachable.

## Recommended run process — one HTTPS link

### 1. Extract and open the correct folder

Extract the ZIP. In VS Code, choose **File → Open Folder** and open the inner `MangoBusSpringReact` folder — the folder that directly contains `backend`, `frontend`, `start-mango.bat`, and this README.

### 2. Set initial Admin credentials (recommended)

Open **Terminal → New Terminal** using PowerShell and set the username and password before the first database initialization:

```powershell
$env:MANGO_ADMIN_USERNAME = "admin"
$env:MANGO_ADMIN_PASSWORD = "Choose-A-Strong-Password"
```

Use a strong password. Keep both variables in the terminal used to start Mango. The Admin password is only used when an Admin user is first created; changing the environment variable after that does not reset the stored account password.

### 3. Start everything with one command

From the project root, run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-mango.ps1
```

Alternatively, double-click `start-mango.bat`.

The script builds React first, checks for an earlier Mango instance and releases its locked JAR if necessary, then opens a second PowerShell window to generate the local certificate, build the Spring Boot executable JAR, and run the application over HTTPS. The parent launcher monitors a small ignored status file so it stops waiting and reports promptly if Maven or Spring Boot fails. It opens the site after the HTTPS health endpoint responds. Keep the backend window open while using Mango.

### 4. Open Mango

**https://localhost:8080**

The health endpoint is **https://localhost:8080/api/health**.

Because the local certificate is self-signed, the browser can warn that the certificate is not trusted. This is expected on first use and does not mean the HTTPS listener failed. You may continue for local development after verifying the address is exactly `https://localhost:8080`. To avoid repeating the warning in a Windows browser, follow the optional certificate steps below.

### 5. Log in

- **Admin:** username `admin`; password is the value configured before the first startup. The demo fallback is `Admin@123` only when no Admin account has been created and no password was configured.
- **Traveller:** use **Create account** to register a regular User.

Registration cannot create administrators.

## Local HTTPS certificate

The first backend startup creates `backend/mango-localhost.p12` with JDK `keytool`; it covers `localhost` and `127.0.0.1`. This certificate and password are only intended for local development, not a public internet deployment. The local certificate-store password is fixed in the development launcher as `mango-local-dev`; it is not an application login or payment secret.

### Optional: trust the certificate in your Windows user profile

After at least one startup generated the certificate, stop the backend with `Ctrl+C`. In the project root, run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\trust-localhost-certificate.ps1
```

Read the prompt and type `TRUST` only if you intend to trust this project's self-signed certificate for local development. It imports the certificate into the **Current User** Trusted Root store; no administrator access is normally required. Restart the browser after installing it. The script requires `keytool` to be available from JDK 21/`JAVA_HOME`.

Only use this certificate for local development. You can remove it later using Windows Certificate Manager (`certmgr.msc`) under **Trusted Root Certification Authorities → Certificates** by locating the certificate named `localhost`/`Mango Local Development`.

## Build commands (manual)

Run these in the project root.

### Build React into Spring Boot resources

```powershell
.\build-frontend.ps1
```

This uses Node/npm, runs the React production build, and copies `frontend/dist/` to `backend/src/main/resources/static/`.

### Package/start the HTTPS application

```powershell
.\start-backend.ps1
```

It finds Java 21, bootstraps Maven if needed, creates the local certificate, runs `mvn clean package`, and starts the executable JAR. Run the frontend build first; or use `start-mango.bat` to do both in order.

## Important: do not use Vite's URL for the one-port experience

`npm run dev` intentionally starts the separate Vite development server at `http://localhost:5173`. It is useful for frontend hot reload, but it is **not** the requested one-link launch mode. For the full site using HTTPS port 8080, always run `start-mango.bat` or `start-mango.ps1`. In the one-port mode, Spring Boot serves both the React site and `/api/**` from `https://localhost:8080`.

## Troubleshooting

### PowerShell says it cannot overwrite variable `HOME`

The launcher now uses `$candidateHomePath` while locating JDK 21. PowerShell variable names are case-insensitive, and `$HOME` is a built-in read-only variable, so `$home` cannot be used as a loop variable. Use the latest fixed ZIP if an earlier copy reports this error.

### `mvn` is not recognized

Use `start-mango.bat` or `start-backend.ps1`; they download Apache Maven into `%LOCALAPPDATA%\MangoDevTools` when a compatible Maven is unavailable. If downloading fails, check internet/proxy access and the official setup instructions at <https://maven.apache.org/install.html>.

### `node` or `npm` is not recognized / MSI error 1603

Use `build-frontend.ps1` / `start-mango.bat`. The script uses a compatible installed Node.js or the official portable Node ZIP. If the download fails, install Node.js LTS from <https://nodejs.org/en/download/> and open a new terminal. The first build must reach `https://registry.npmjs.org` to download React dependencies.

### The script says `frontend/dist/index.html` was not generated

Look above that message for the first npm or TypeScript error. Confirm internet access, then run the launcher again. Do not manually create a fake `index.html` in the backend static folder.

### Browser opens `http://localhost:5173` instead of HTTPS 8080

Close the Vite development server if it is running. Run `start-mango.bat` from the project root, then open **https://localhost:8080**. Do not use `npm run dev` for the one-port setup.

### HTTPS opens but a browser security warning appears

The local development certificate is self-signed. You can proceed for local testing after checking the address, or import it into the current Windows user store with `trust-localhost-certificate.ps1` as described above.

### Maven clean says the JAR is being used by another process

This happens when an older Mango backend is still running and holds `backend/target/mango-bus-api-1.0.0.jar` open. The updated `start-mango.ps1` and `start-backend.ps1` invoke `stop-existing-mango.ps1` before a rebuild. It only stops a Java process whose command line shows the Mango executable JAR name (`mango-bus-api-1.0.0.jar`), including a previous extracted copy; it never force-stops an unrelated Java process. If it reports that port 8080 belongs to another application, close that application yourself and retry. You can inspect the listener with `Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess`.

### Port 8080 is occupied

The launcher checks port 8080 before compiling. It will report the process ID rather than killing an unrelated process. Close the application using port 8080, then run `start-mango.bat` again. The configured default is `https://localhost:8080`.

### Booking/API errors

Keep the backend terminal open and inspect the first Java exception. Check `https://localhost:8080/api/health`. Do not delete `backend/data/` as a troubleshooting step unless you intend to erase local accounts, routes, and bookings; back it up first.

## Security notes

- Passwords are stored as BCrypt hashes.
- Spring Security enforces Admin/User permissions on the backend.
- The HTTPS certificate and local H2 database are local development assets and are not included in Git.
- A self-signed certificate is acceptable for localhost development only. Public deployment requires a certificate from a trusted CA, production secrets management, database backups, monitoring, and a security review.
- No Razorpay, UPI, checkout or online payment feature is configured.
